## Platform

web

## Stack

React (Vite) + Supabase (database; keys supplied later by the owner). Hosting: GitHub repo `brunoalvaress1/prime-pages`, deployed on Vercel with the domain primepagesleme.com.br. AI generation (text-to-site and URL reverse engineering) is deferred: the front ships with a local simulation behind a service layer, to be wired to a server-side AI later.

## Users

Small-business owners, local merchants, self-employed professionals and liberal professionals in Leme-SP and region who need a website or a management system but cannot describe it in technical terms. They usually arrive with a reference ("I want one like this site") rather than a spec.

Secondary user: the Prime Page team, who receives the finished model on WhatsApp and must quote it without missing scope.

## Product Purpose

Prime Page is a web studio that builds hand-made websites, landing pages and custom management systems. The new site does two jobs:

1. Show what the studio does and the real projects it has shipped.
2. Let a prospect build the site or system they want themselves (the "Construa o seu site" builder, highlighted in the nav), then send it for a quote on the company WhatsApp with a scope summary.

Success: a prospect leaves the builder with a model they recognise as "theirs", and the team receives a WhatsApp message whose summary (payments, database, login, integrations, page count, etc.) is complete enough to quote without surprises.

## Positioning

The prospect does not fill a contact form; they assemble the actual site: start from a ready model, from a reference URL the studio reverse-engineers, or from a written description, then customise sections, images, colours and 3D. Systems get the same treatment: the prospect sees modules and how the system would work before paying anything.

## Capabilities and Constraints

- Builder: templates, section add/remove/reorder, text and image editing, colour/theme, optional 3D element, preview desktop/mobile.
- Entry modes: ready templates, reference URL (reverse engineering, simulated for now), written prompt (simulated for now).
- System mode: choose a system type and modules; show the flow of how it would work.
- Quote handoff: WhatsApp deep link with summary flags (payments, database, login/users, admin panel, integrations, 3D, page count, domain/hosting).
- Supabase stores saved projects/quote requests once keys exist; the site must work without them.
- Undecided: pricing values (never show prices; the team quotes), AI provider.

## Product Principles

1. Show, don't ask: the prospect builds instead of describing.
2. A reference is a starting point, not a limit: everything copied is editable.
3. Nothing leaves without scope: every quote carries the flags that change price.
4. Real work as proof: only shipped projects and true numbers.
